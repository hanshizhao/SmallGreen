## 问题清单

### 问题1: [严重] 触发器重置后失败会导致数据丢失

**位置**: `SubSystem.cs:110-125`

```csharp
// 先将触发点位由1重置为0
if (bulk.TriggerComplete != null)
{
    bulk.TriggerComplete.NewValue = 0;
    var r = await PLC.Write(bulk.TriggerComplete);
    // 如果后续步骤失败，触发器已经是0，数据永久丢失
}
```

**问题描述**:
- 当前逻辑在处理配液完成时，首先将触发器从1重置为0
- 如果后续步骤（数据库查询、PLC读取、数据保存）失败，触发器已经被重置
- 下次轮询时触发器值为0，不会再处理这次配液完成事件
- **结果**: 配液数据永久丢失

**影响范围**: 数据完整性

**建议修复方向**:
1. 将触发器重置操作移到数据成功保存之后
2. 或在失败时尝试恢复触发器为1
3. 或引入状态机，记录处理中的状态

### 问题2: [严重] `CheckBulkCompleted` 缺少异常处理

**位置**: `SystemManagerService.cs:89-107`

```csharp
public async Task CheckBulkCompleted()
{
    foreach (var subSystem in ListSubSystem)
    {
        foreach (var equip in subSystem.ListEquipment)
        {
            foreach (var bulk in equip.ListBulk)
            {
                var trigger = bulk.TriggerComplete;
                if (trigger == null) continue;
                if (trigger.GetCurrentValue() != 1) continue;

                // 如果 SavePRCSData 抛出异常，整个循环中断
                var result = await subSystem.SavePRCSData(equip, bulk);
                if (!result.IsSuccess) logger.LogError(result.Message);
            }
        }
    }
}
```

**问题描述**:
- 方法内部没有 try-catch
- 如果 `SavePRCSData` 抛出异常（而非返回失败结果），整个循环会中断
- 后续的配液缸无法被处理
- 日志只记录 `result.Message`，缺少子系统/设备/配液缸的上下文信息

**影响范围**: 系统稳定性、问题排查

**建议修复方向**:
1. 在内层循环添加 try-catch
2. 增强日志，记录完整的上下文信息（子系统名、设备名、配液缸编号）

### 问题3: [中等] `LastCompleteTime` 未更新

**位置**:
- 定义: `Bulk.cs:57`
- 使用: `SubSystem.cs` 中的 `SavePRCSData` 方法从未更新此字段

```csharp
// Bulk.cs 中的定义
/// <summary>
/// 上次配液完成时间
/// </summary>
[SugarColumn(IsJson = true)]
public DateTime LastCompleteTime { get; set; }
```

**问题描述**:
- `Bulk` 实体类定义了 `LastCompleteTime` 字段
- 但 `SavePRCSData` 成功后从未更新这个字段
- 数据库中该字段始终为默认值

**影响范围**: 数据追踪、业务查询

**建议修复方向**:
1. 在 `SavePRCSData` 成功保存数据后，更新 `bulk.LastCompleteTime = DateTime.Now`
2. 需要同时更新数据库中的记录

### 问题4: [中等] 没有事务保护

**位置**: `SubSystem.cs:350-361`

```csharp
var n = await new Repository<PRCSData>().Context.InsertNav(prcsData)
    .Include(it => it.ListDetail)
    .ExecuteCommandAsync();

if (!n)
{
    return new OperateResult<PRCSData>
    {
        IsSuccess = false,
        Message = $"{equipment.Name}-{bulk.CodeNumber} 配液完成时，保存数据到数据库失败"
    };
}
```

**问题描述**:
- 数据库保存操作没有显式事务
- `InsertNav` 可能涉及多条记录插入（主表+明细表）
- 如果部分数据保存失败，可能产生不一致数据

**影响范围**: 数据一致性

**建议修复方向**:
1. 使用 SqlSugar 的事务机制包装保存操作
2. 确保主表和明细表的原子性操作

### 问题5: [低] 性能问题 - 助剂信息无缓存

**位置**: `SubSystem.cs:128`

```csharp
// 查询助剂信息
var resultAssList = await AssInfo.GetAssInfo();
```

**问题描述**:
- 每次配液完成都会查询数据库获取助剂信息
- 助剂信息通常是相对静态的数据，不会频繁变更
- 频繁查询数据库影响性能

**影响范围**: 系统性能

**建议修复方向**:
1. 引入内存缓存（如 `IMemoryCache`）
2. 或在系统初始化时加载到内存，定时刷新
3. 或使用 SqlSugar 的二级缓存

### 问题6: [低] 潜在并发安全问题

**位置**: `SmallGreenBackgroundService.cs:40-48`

```csharp
while (!stoppingToken.IsCancellationRequested)
{
    try
    {
        await SystemManagerService.CheckRuntime();
        await SystemManagerService.CheckBulkCompleted();
        await Task.Delay(TimeSpan.FromSeconds(2), stoppingToken);
    }
    // ...
}
```

**问题描述**:
- 轮询间隔为2秒
- 如果 `SavePRCSData` 执行时间超过2秒（网络延迟、数据库慢等）
- 虽然触发器会被重置，但理论上存在竞态条件
- 同一个配液缸可能被并发处理

**影响范围**: 数据一致性（概率较低）

**建议修复方向**:
1. 引入处理锁，标记正在处理的配液缸
2. 或使用 `ConcurrentDictionary` 记录处理状态
3. 或在 `Bulk` 类添加 `IsProcessing` 标志
